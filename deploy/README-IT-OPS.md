# KOL CRM 中心系统运维与故障定位说明

本文供公司 IT 和项目维护人员使用，适用于“中心网页 + 员工本地达人采集助手”的部署方式。

## 1. 系统由哪两部分组成

### 中心服务器

中心服务器负责：

- 提供所有员工共同访问的网页；
- 保存达人库、任务、筛选结果和建联状态；
- 执行业务规则、AI 画像、AI 话术和数据库读写；
- 保存并分发需要员工电脑执行的 Agent 任务；
- 接收员工 Agent 返回的执行进度和结果。

中心服务器上的 PM2 应同时运行：

- `kol-crm-web`：网页和 API；
- `kol-crm-worker`：后台任务处理。

### 员工本地 Agent

“达人采集助手.exe”运行在员工自己的 Windows 电脑，负责必须使用本机 Chrome 的操作：

- 抖音关键词采集；
- 达人主页补齐；
- 视频数据回访；
- 抖音私信发送。

员工电脑不直接连接公司数据库，也不需要对外开放端口。

## 2. 什么是“Agent 中心任务通道”

可以把它理解为一个由中心服务器管理的安全任务队列。

一次采集的实际流程如下：

1. 员工在中心网页点击“开始采集”。
2. 中心网页把任务写入中心数据库，并指定给所选的在线 Agent。
3. 员工电脑上的 Agent 主动向中心服务器询问是否有新任务。
4. Agent 领取任务后，在该员工电脑启动或复用 Chrome 并执行采集。
5. Agent 持续把进度、日志、成功结果或错误回传中心服务器。
6. 中心服务器根据结果执行去重、画像、筛选和入库。
7. 所有员工在网页上看到同一份共享结果。

简化理解：

```text
员工浏览器 -> 中心网页/数据库 -> 中心任务队列
                                  ^        |
                                  |        v
                           执行结果 <- 本地 Agent -> 本机 Chrome
```

它不是让中心服务器远程打开员工电脑，也不是让网页直接访问员工电脑的 `127.0.0.1`。连接由本地 Agent 主动发起，因此员工电脑通常不需要公网 IP、端口映射或入站防火墙规则。

`CENTRAL_AGENT_TOKEN` 用于确认连接的是公司分发的 Agent。服务器配置的密钥必须与员工包中的 `central-agent.conf` 一致，不能发到普通群聊或写进截图。

## 3. 如何快速判断故障在哪一端

### 优先检查中心服务器

出现以下情况时，通常指向中心网页、Worker、数据库或中心配置：

- 所有员工同时无法打开网页；
- 出现 502、504、白屏或 API 服务不可用；
- 所有人都无法读取或保存达人库；
- 多人看到的任务、达人状态或建联状态无法同步；
- 报数据库连接失败、数据表不存在或 Prisma 错误；
- 所有人的 AI 画像或 AI 话术同时失败；
- 多台电脑的任务都一直排队；
- Agent 显示已连接中心，但网页仍无法发现任何在线 Agent；
- 网页更新后，所有员工出现相同错误。

### 优先检查员工本地 Agent

出现以下情况时，通常指向某台员工电脑：

- 只有一名员工失败，其他员工正常；
- Chrome 没有打开；
- 抖音登录状态丢失；
- 私信只填入输入框但没有发送；
- 视频数据回访抓取失败；
- 出现 CDP、9222、17321、Playwright、MediaCrawler、Python、DLL、`greenlet` 或 `cache` 错误；
- 网页提示该电脑的采集助手离线；
- Windows 安全软件拦截 EXE、Python 或 Chrome。

### 快速判断口诀

- 所有人都失败：先查中心服务器。
- 只有一台失败：先查本地 Agent。
- 数据共享、读写、AI 失败：先查中心端。
- Chrome、采集、回访、私信失败：先查员工端。
- Agent 在线但任务领取失败：中心通道和 Worker 两端都查。

## 4. IT 排查中心服务器的顺序

### 4.1 检查网站和进程

```bash
curl -I http://127.0.0.1:3000
curl http://127.0.0.1:3000/api/health
pm2 status
```

`kol-crm-web` 和 `kol-crm-worker` 都应为 `online`。

### 4.2 查看日志

```bash
pm2 logs kol-crm-web --lines 200
pm2 logs kol-crm-worker --lines 200
```

重点关注：数据库连接、缺少数据表、环境变量、Agent 鉴权、任务领取和任务回传错误。

### 4.3 检查 Nginx

```bash
sudo nginx -t
sudo systemctl status nginx
```

### 4.4 按需重启

仅网页/API 异常：

```bash
pm2 restart kol-crm-web
```

任务一直排队、无法调度或后台处理停止：

```bash
pm2 restart kol-crm-worker
```

代码、Prisma、环境变量或任务通道配置更新后：

```bash
pm2 restart kol-crm-web kol-crm-worker --update-env
```

Nginx 配置改动并通过检测后：

```bash
sudo systemctl reload nginx
```

不要遇到任何问题都直接重启整台服务器。优先保留日志，再重启对应 PM2 进程。

## 5. 哪些修改需要重新部署中心网页

以下修改需要更新服务器代码，并通常需要重新构建和重启中心服务：

- 页面和中心 API 修改；
- 数据库结构或 Prisma Schema 修改；
- AI 画像、AI 话术和业务筛选规则修改；
- 中心任务队列、Agent API 或 Worker 修改；
- 服务器环境变量修改。

以下修改一般只需重新分发 portable 包，不需要更新中心服务器：

- Chrome 启动或登录状态处理；
- MediaCrawler、Playwright 和本地 Python 依赖；
- 本地采集、主页补齐、数据回访或私信点击逻辑；
- “达人采集助手.exe”的启动和托盘行为。

如果同时修改了“中心下发的任务格式”和“Agent 接收的任务格式”，中心服务器和 portable 包必须同步升级，否则可能出现 Agent 在线但任务执行失败。

## 6. IT 应保存的部署信息

- 项目部署目录；
- PM2 应用名称；
- Nginx 配置文件位置；
- 数据库地址、数据库名和备份恢复方式；
- `.env.production` 的位置；
- Agent 通信密钥在服务器上的配置位置；
- 发布、构建、重启和日志查看命令；
- 当前中心版本与当前 portable 版本；
- HTTPS 证书续期方式。

数据库密码、AI Key 和 Agent 通信密钥不得提交到 Git，也不要通过普通群聊发送。

## 7. 报障时需要提供什么

为避免只能看到“失败”而无法定位，请保留并提供：

- 出错时间，精确到分钟；
- 操作员工和所选 Agent 名称；
- 页面错误截图；
- 任务编号（页面若有显示）；
- 对应时间段的 `kol-crm-web` 和 `kol-crm-worker` 日志；
- 如果只影响一台电脑，再提供本地 Agent 日志；
- 是否所有员工都失败，还是只有一台电脑失败。
